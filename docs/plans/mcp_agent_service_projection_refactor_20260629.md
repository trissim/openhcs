# MCP Agent Service Projection Refactor

Date: 2026-06-29

## Problem

The largest MCP mirrors are covered in the capability, UI bridge, plate/viewer,
and dev-client plans. A second tier remains in agent services and MCP context
code. These are smaller, but still violate the same boundary: an agent service
or MCP adapter is declaring facts that already have a typed owner.

Current mirrors:

- `AgentConfigKind` in `openhcs/agent/services/config_service.py` hardcodes
  global vs pipeline config classes and aliases.
- `ParameterDocumentationPolicy` in
  `openhcs/agent/services/function_catalog_service.py` owns supplier labels
  such as `runtime_primary_input` and derives primary-input semantics by
  positional heuristic.
- `CatalogFilterText.DOMAIN_TOKEN_ALIASES` is a search synonym table inside the
  function catalog.
- `OPENHCS_AGENT_CONTEXT_SOURCE_TYPES` in `openhcs/mcp/context.py` manually
  mirrors service fields in `OpenHCSAgentContext`.
- `openhcs/mcp/server.py` contains enum coercion helpers such as
  `_object_state_field_filter()` and `_window_snapshot_capture_scope()` that
  duplicate enum accepted-value formatting.
- `openhcs_register_custom_function()` builds function IDs as
  `openhcs:{registered_function.__name__}` instead of asking the registry or
  custom-function manager for the registered ID.

## Existing Authorities

- `GlobalPipelineConfig`, `PipelineConfig`, and generated config decorators in
  `openhcs.core.config` own config types.
- `CallableRuntimeConfig.registered_config_types()` and
  `StepConfigUniverse` already show the type-driven config discovery pattern.
- `CallableContract`, runtime-bound parameter declarations, artifact input
  declarations, runtime adapter declarations, and
  `python_introspect.parameter_exclusions()` own callable parameter source
  semantics.
- The unified registry and `FunctionMetadata` own function IDs.
- `OpenHCSAgentContext` dataclass fields own service instances available to the
  MCP context.
- Enum classes already own accepted values; shared parsing helpers should live
  with DTO/enum utilities, not per MCP wrapper.

## Target Shape

### Config service

Delete `AgentConfigKind` as a hand-maintained enum.

Replace it with a typed config resolver:

```python
@dataclass(frozen=True, slots=True)
class AgentConfigDeclaration:
    config_type: type[GlobalPipelineConfig | PipelineConfig]
    aliases: tuple[str, ...]
```

The declaration list must be derived from the config classes themselves where
possible:

- primary accepted name is `config_type.__name__`;
- short alias can be declared on the config class or generated by a small typed
  policy, not hardcoded in a parallel enum;
- validation error messages are generated from the declarations.

Do not extend this into step config ownership. Step config discovery already
belongs to `StepConfigUniverse`.

### Function parameter source labels

Replace string supplier constants with nominal parameter-source declarations.

Target:

```python
class FunctionParameterSource(str, Enum):
    AGENT = "agent"
    PRIMARY_INPUT = "runtime_primary_input"
    ARTIFACT_INPUT = "runtime_artifact_input"
    RUNTIME_PARAMETER = "runtime_parameter"
    RUNTIME_ADAPTER = "runtime_adapter"
```

This enum or declaration family must be owned by callable contract projection,
not buried in function catalog display code.

Then update `ParameterDocumentationPolicy.supplied_by()`:

- primary input comes from callable contract/input binding authority if
  available;
- artifact inputs come from `CallableContract.artifact_input_names`;
- runtime-bound inputs come from runtime-bound parameter declarations;
- runtime adapter input comes from the runtime adapter declaration.

If a callable contract does not yet expose primary-input identity, add that
contract property there. Do not preserve positional fallback as the long-term
semantic authority. If a temporary fallback is needed during migration, mark it
as a failing TODO test and remove it in the same batch before commit.

### Function catalog search aliases

`DOMAIN_TOKEN_ALIASES` is not execution semantics; it is search ranking policy.
It can remain, but it should be named and isolated as `AgentFunctionSearchPolicy`
or similar. The function catalog should not look like it owns biological module
semantics.

Rules:

- aliases may improve search recall;
- aliases must not affect function identity, callable contract, or pipeline
  generation;
- tests should assert aliases only affect ranking/matching.

### MCP context source freshness

Delete `OPENHCS_AGENT_CONTEXT_SOURCE_TYPES`.

Derive source-watch paths from:

- `dataclasses.fields(OpenHCSAgentContext)`;
- each field value type after context construction; or
- service provider declarations if the context becomes declaration-backed.

The source-freshness watchlist should not require manually adding a service
class every time a field is added to `OpenHCSAgentContext`.

### Enum coercion in MCP server

Move repeated accepted-value formatting into a shared DTO utility:

```python
def coerce_enum(enum_type: type[EnumT], value: str, field_name: str) -> EnumT:
    ...
```

MCP wrappers can call this helper, but they should not each own accepted-value
strings. If a specific enum needs custom aliases, that alias policy belongs with
that enum/declaration.

### Custom function IDs

Change `openhcs_register_custom_function()` to obtain function IDs from the
authority that registered the function:

- preferred: `CustomFunctionManager.register_from_code()` returns registration
  records with function ID and path;
- acceptable: function catalog/registry service resolves IDs for the returned
  function objects through the unified registry.

Do not construct `openhcs:{__name__}` in MCP.

## Deterministic Steps

1. Refactor config resolver.
   - Add typed config declaration resolver.
   - Replace `AgentConfigKind.from_request()`.
   - Add tests for `global`, `GlobalPipelineConfig`, `pipeline`, and
     `PipelineConfig`.
   - Add a test that error text is generated from resolver declarations.

2. Introduce function parameter source declaration.
   - Add enum/declaration near callable contract projection DTOs.
   - Update `FunctionParameterSpec.supplied_by` to use its `.value` only at DTO
     serialization.
   - Remove supplier string constants from `ParameterDocumentationPolicy`.
   - Add tests for primary input, artifact input, runtime-bound input, runtime
     adapter input, and hidden parameters.

3. Isolate search policy.
   - Move stop words and domain aliases into a named search policy object.
   - Keep it explicitly display/search only.
   - Add a ranking-only test for alias behavior.

4. Derive source freshness from context fields.
   - Replace `OPENHCS_AGENT_CONTEXT_SOURCE_TYPES`.
   - Add a test that adding a fake dataclass field to a test context updates
     watched source types without editing a tuple.

5. Add shared enum coercion.
   - Move accepted-value formatting into a shared helper.
   - Replace `_object_state_field_filter()` and
     `_window_snapshot_capture_scope()`.
   - Add tests for error messages.

6. Fix custom function ID authority.
   - Extend custom function registration result or registry lookup to return
     function IDs.
   - Update MCP tool to use returned IDs.
   - Add a test that registered ID equals the registry key and is not assembled
     from a hardcoded prefix in MCP.

## Implementation Progress

2026-06-29 implementation:

- `AgentConfigKind` was removed. `AgentConfigDeclaration` now resolves
  `GlobalPipelineConfig` and `PipelineConfig` from typed config declarations
  and aliases.
- `FunctionParameterSource` is a nominal DTO enum instead of string constants
  buried in display policy.
- `CallableContract.primary_input_parameter_name` now owns the primary
  FunctionStep input-parameter identity. `ParameterDocumentationPolicy` asks
  the callable contract instead of choosing the first positional parameter
  itself.
- `AgentFunctionSearchPolicy` isolates search-only stop words and biological
  token aliases from callable/function semantics.
- `openhcs_agent_context_source_types()` derives source-watch owner types from
  `OpenHCSAgentContext` dataclass fields.
- MCP enum coercion uses shared `coerce_enum()` from
  `openhcs.core.runtime_semantics`; the MCP-local enum helpers were removed.
- `openhcs_register_custom_function()` resolves registered function IDs through
  `FunctionCatalogService.function_ids_for_callables()` instead of constructing
  `openhcs:{registered_function.__name__}` in MCP.
