\section{Representative Readings of the Realizability Criterion}\label{sec:evaluation}
%==============================================================================

This section does not add new theorem-level content; it records representative theorem instantiations of Theorem~\ref{thm:ssot-iff} on familiar host systems once the structural properties are fixed. In particular, the realizability theorem yields a host-classification criterion: verifiable independent rate $1$ is possible exactly when causal propagation and provenance observability are both host-native. The tables are illustrative rather than exhaustive, and no theorem in the paper depends on the particular platform list.

\begin{corollary}[Computational-Realization Criterion]\label{cor:lang-realizability}
A computational platform realizes verifiable independent rate $1$ for structural facts if and only if it combines automatic propagation of derived representations with queryable provenance for those representations.
\end{corollary}
\leanmeta{\LH{LNG1}}

The corollary is a direct restatement of Theorem~\ref{thm:ssot-iff}. What changes across examples is the host mechanism that provides propagation and provenance, not the criterion itself. Among the programming-language runtimes examined here, drawn from the top-10 TIOBE languages and documented in full in Supplement~A~\cite{tiobe2024}, only Python satisfies both conditions natively; the remaining runtimes fail on one or both conditions under the runtime-only interpretation used in this paper. This is not a statement about language quality, but about which mathematical conditions are satisfied by the host semantics being examined.

The Python--Java contrast illustrates the classification sharply. For the structural facts considered here, Python supplies definition-time hooks (such as class-creation hooks) that propagate structural updates and runtime hierarchy introspection that exposes derivation provenance, so the theorem permits verifiable unit rate inside the runtime itself. Under the same runtime-only interpretation, Java exposes reflection over loaded classes but does not make annotation-driven derivation relationships host-native at JVM runtime, so the provenance condition fails and the theorem rules out verifiable unit rate without external tooling.

The same question is asked in each domain: does the host provide both causal propagation and provenance observability? Tables~\ref{tab:host-checks-a} and~\ref{tab:host-checks-b} record representative answers across programming-language runtimes, database patterns, and dependency-resolution systems.
